### The Key Insight
Instead of hitting ONE model's rate limit:
```
Model A: 100 req/hour limit → Hit after 100 requests
```

Distribute across TEN models:
```
Model A-J: 100 req/hour each → 1000 req/hour total capacity!
```

### Intelligent Distribution
```python
from or_client_v2 import get_openrouter_client

client = get_openrouter_client()

# JARVIS automatically:
# 1. Selects best model based on health/load
# 2. Sends request to that model
# 3. If rate limited, tries next model
# 4. Returns response from first successful model

response = client.call(messages)  # Automatic!
```

## 💡 Load Balancing Strategies

### LEAST_LOADED (Recommended)
Routes to model with fewest active requests. Best for production.

### ROUND_ROBIN
Simple rotation through models. Good for testing.

### FASTEST
Routes to fastest-responding model. Minimize latency.

### LOWEST_RATE_LIMIT
Routes to model with most remaining quota. Maximize throughput.

### WEIGHTED_RANDOM
Random selection weighted by health. Best for resilience.

## 📈 Architecture Overview

```
JARVIS Request
       ↓
[Model Router]
       ↓ (Selects best model)
[Rate Limiter] (Per-model quotas)
       ↓
[Request Queue] (Prioritization)
       ↓
[Cache Manager] (Return if cached)
       ↓
[Model Selection] (A-J)
       ↓
[OpenRouter API]
       ↓
Response → Cache → JARVIS
```
